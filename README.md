# NEO ORACLE ARCADE — Web版 (v1.0)

「運命の四連スロット」Discord Botのスタンドアロン Web版。ガチャ・プロフィール・履歴・ランキング・
ショップ・インベントリ・キャラ育成/とくぎ変更のソロプレイ経済ループに加え、リアルタイムPvPバトル、
部屋制の協力ボスレイド、運営お知らせ配信、PWA(ホーム画面インストール)対応まで実装しています。

## 構成

```
/server            Express + Socket.IO + Prisma API サーバー
  /src/battle        PvPバトルの対戦エンジン・マネージャー
  /src/raid          協力ボスレイドの対戦エンジン・マネージャー
  /src/socket        Socket.IO 接続/認証/ハンドラ
/web                React + Vite フロントエンド
/packages/game-core  ガチャ抽選ロジック・アイテム・レアリティ・バトル/レイド定数などの共有データ
```

## セットアップ

DB は PostgreSQL を使用します。[Neon](https://neon.tech) 等の無料枠でプロジェクトを作成し、接続文字列を
`server/.env` の `DATABASE_URL` に設定してください。

```bash
npm install

# .env.example を参考に server/.env を作成し、DATABASE_URL に Postgres 接続文字列を設定
# 本番環境では JWT_SECRET / ADMIN_SIGNUP_CODE も必ず変更してください。

npm run build -w packages/game-core
npm run prisma:migrate -- --name init
```

## 開発起動

2つのターミナルで実行してください。

```bash
npm run dev:server   # http://localhost:4000
npm run dev:web      # http://localhost:5173
```

ブラウザで `http://localhost:5173` を開き、新規登録すると最初のユーザーが自動的に管理者(role=admin)になります。

> Vite の依存プリバンドルキャッシュが `packages/game-core` の変更を拾わないことがあります。
> 画面が真っ白になり、コンソールに `does not provide an export named ...` のようなエラーが出た場合は
> `rm -rf web/node_modules/.vite` を実行してから `npm run dev:web` を再起動してください。

## 対戦機能

### ⚔️ バトル(1対1)

`/battle` から表示名でオンラインの相手を検索して挑戦できます。相手が承諾すると専用のバトルルーム
(`/battle/:roomId`)に自動遷移します。

- キャラクター選択 → ターン制バトル(こうげき/ぼうぎょ/とくぎ/一か八か/アイテム/リタイア)
- SPD順に行動が解決され、被ダメージ・回復はHPバー上にフローティング数値でアニメーション表示
- 行動ログは1行ずつ時間差で表示され、戦闘の流れを追いやすくしています
- 切断後20秒操作が無ければ自動的にリタイア扱いになります

### 🐉 レイド(最大4人協力)

`/raid` で部屋の名前とボスを指定してロビーを作成できます。他のプレイヤーは一覧から参加でき、
主催者が開始するとキャラクター選択 → ボス討伐バトルに進みます。

- ボスは6種(業火の悪魔ゲヘナ/氷結の女王リリス/深淵の竜王ヴァルガ/暴風の魔人ヴォルテクス/
  深淵の蜘蛛女王アラクネ/闇の魔導士シェイド)。参加人数に応じてHP/ATKがスケーリングされます
- 5ラウンドごとの弱点(与ダメ1.5倍)、ボス専用技、状態異常(火傷/毒/凍結/封印/攻撃力低下)を再現
- 討伐成功で全員に報酬、最多ダメージのMVPには追加ボーナス、確率でボスドロップ専用アイテムを入手
- 途中離脱・切断時も残りメンバーで討伐を継続できます

## 運営(管理者)権限

`server/.env` の `ADMIN_SIGNUP_CODE`(開発用デフォルト: `ORACLE-STAFF-2026`)を運営スタッフに共有してください。
このコードは以下のどちらかで使用できます。

- 新規登録画面の「運営コード」欄に入力して登録する
- 既存アカウントでログイン後、プロフィール画面の「運営コードで昇格」から入力する

管理者になると、ナビゲーションに「⚙️ 運営」パネルが表示され、以下が行えます。

- ユーザー検索(表示名/メールアドレス)
- 任意のユーザーへのコイン付与(上限なし)
- 任意のユーザーへのアイテム付与(ショップ品・ボスドロップ専用品どちらも指定可、上限なし)
- 登録済み全ユーザーへのアイテム一括配布
- 運営限定キャラクターの付与(ガチャの抽選対象外。国籍・年齢・性別・特徴・隠し特徴・とくぎ属性を
  自由に入力して作成し、常に⭐KMR「完璧マスターランク」として任意のユーザーへ直接付与できます。
  KMRはガチャの重み(weight)が0のためガチャからは絶対に出現しません)

本番運用では `ADMIN_SIGNUP_CODE` を必ず推測されにくい値に変更してください。

## 🔑 パスワード再設定

ログイン画面の「パスワードを忘れた方はこちら」からメールアドレスを入力すると再設定リンクが発行されます。
現状メール送信基盤(SMTP)は組み込んでいないため、リンクは**サーバーのコンソール**に出力されます。

```
[パスワード再設定] user@example.com 宛のリンク: http://localhost:5173/reset-password?token=... (有効期限30分)
```

運営はこのログからリンクを取得し、本人確認のうえで該当ユーザーに個別案内してください。リンクは30分で
失効し、一度使用すると再利用できません。メールアドレスの登録有無に関わらず同じ完了メッセージを返すため、
第三者にアカウントの存在を推測されることはありません。

## 📢 お知らせ配信

`/announcements` で全ユーザーがお知らせ一覧を閲覧できます。運営パネルの「お知らせを送信」から
タイトル・本文を投稿でき、コイン・アイテムを任意で添付すると送信と同時に全ユーザーへ自動配布されます
(配布は投稿した瞬間の登録ユーザー全員が対象で、後から登録したユーザーには遡って付与されません)。

宛先を「全員」ではなく検索・選択した特定の1ユーザーに絞ると、そのユーザーだけに見える**個人メッセージ**
になります(例: バグ報告への個別のお礼)。個人メッセージには⭐運営限定キャラクター(KMR)を添えることも
でき、コイン・アイテムと同様に送信と同時に付与され、受け取ったユーザーの「お知らせ」画面に理由付きの
履歴として残り続けます。

## 📱 PWA(ホーム画面への追加)

`web/public/manifest.webmanifest` と `web/public/sw.js` によりPWA化されています。HTTPSで公開すると、
スマートフォンのブラウザから「ホーム画面に追加」でアプリのようにアイコン起動・全画面表示ができます。
アイコンは `web/public/icons/` にあります(差し替える場合は同じファイル名で上書きしてください)。

## 🚀 デプロイ

### 無料構成(Render + Neon)

1. [Neon](https://neon.tech) で無料のPostgresプロジェクトを作成し、接続文字列(`DATABASE_URL`)を控える
2. GitHubにこのリポジトリをpush
3. [Render](https://render.com) で「New +」→「Web Service」→ GitHubリポジトリを選択
   - Environment は「Docker」を選択(リポジトリの `Dockerfile` を自動検出)
   - Instance Type は無料の「Free」を選択
4. 「Environment」タブで環境変数を設定
   - `DATABASE_URL`: 手順1のNeon接続文字列
   - `JWT_SECRET`: 長いランダム文字列
   - `ADMIN_SIGNUP_CODE`: 運営コード(推測されにくい値)
   - `WEB_ORIGIN`: デプロイ後にRenderが発行する公開URL(例: `https://xxxx.onrender.com`)
   - `NODE_ENV`: `production`
   - `PORT` はRenderが自動で注入するため設定不要
5. デプロイが完了すると公開URLでアクセス可能になります。コンテナ起動時に `prisma migrate deploy` が
   自動実行されるため、スキーマ変更後の再デプロイもgit pushだけで反映されます

無料枠は一定時間アクセスが無いとスリープし、次のアクセス時に数秒〜数十秒の起動待ちが発生します
(Neon側もアイドル時にスリープしますが、次のクエリで自動的に復帰します)。

### Dockerで自前ホスティングする場合

```bash
cp .env.docker.example .env
# .env を編集して DATABASE_URL(Postgres接続文字列) / JWT_SECRET / ADMIN_SIGNUP_CODE / WEB_ORIGIN を設定

docker compose up -d --build
```

起動すると `docker-compose.yml` で指定したポート(デフォルト4000番)でAPIとフロントの両方が同一オリジンから
配信されます。

Dockerを使わない場合は以下でも本番起動できます。

```bash
npm run build
NODE_ENV=production node server/dist/index.js
```

この場合、サーバーは `web/dist` の静的ファイルとSPAのフォールバックを自動で配信します(`NODE_ENV=production`
かつ `web/dist` が存在する場合のみ)。

## データベース

PostgreSQLを使用します。[Neon](https://neon.tech) や [Supabase](https://supabase.com) の無料枠、
またはローカル/自前のPostgresを `DATABASE_URL` に指定してください。

## 動作確認

- 新規登録 → ログイン
- ガチャ(1連/10連/SR以上確定/SSR以上確定)を実行し、コインが減りキャラが増えることを確認
- プロフィール/履歴(レアリティ絞り込み・ページネーション)/ランキングを確認
- ショップでアイテム購入 → インベントリに反映されることを確認
- キャラ育成でレベルアップ、SSR以上のキャラでとくぎ属性変更を確認(同じ属性への変更はボタンが無効化されます)
- 2アカウントでバトルの挑戦→対戦→決着までを確認
- レイドで部屋作成→開始→討伐(または敗北)までを確認
- `npm run prisma:studio` で実データを確認可能

## 既知の制約

- サーバーは単一プロセス前提です(対戦・レイドの状態はメモリ上で管理しており、水平スケールには対応していません)
- 無料ホスティングはアイドル時にスリープするため、初回アクセス時に起動待ちが発生します
